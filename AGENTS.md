# AGENTS.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Commands

**Run the development server**
```bash
python run.py
```
The app starts on `http://localhost:5000`.

**Run tests**
```bash
python -m pytest tests/
# Single test:
python -m pytest tests/test_basic.py::test_health_check
```
The test suite uses `TestingConfig` which connects to an in-memory SQLite database — no real DB connection needed.

**Lint and format**
```bash
black .
isort .
flake8
```
Black is configured with `line-length = 88`, `target-version = py39`. Isort uses `profile = "black"`. Migrations folder is excluded from formatting.

**Database migrations**
```bash
flask db migrate -m "Description"   # generate migration
flask db upgrade                     # apply migrations
flask db downgrade                   # revert last migration
```

**Load testing**
```bash
locust -f locustfile.py --host=http://localhost:5000
```

**Production**
```bash
gunicorn -w 4 -b 0.0.0.0:5000 "app:create_app()"
```

**Custom CLI commands** (defined in `run.py`)
```bash
flask init-db       # create all tables
flask create-admin  # print existing admin credentials
```

## Environment Setup

Copy `.env.example` to `.env` and fill in the values. Required keys:
- `SECRET_KEY`, `JWT_SECRET_KEY`
- `DATABASE_URL` — primary DB URI (PostgreSQL in `.env.example`; production uses a remote MySQL/MariaDB)
- `DEV_DATABASE_URL` — optional override for development (falls back to `DATABASE_URL`)

`FLASK_ENV` controls which config class is loaded (`development`, `production`, `testing`). It defaults to `development`.

> **Note**: `requirements.txt` has an unresolved git merge conflict between `pg8000` and `psycopg2-binary`. Resolve this before installing dependencies by picking the correct PostgreSQL driver for the target environment.

## Architecture

### Application Factory

`app/__init__.py` uses Flask's application factory pattern. `create_app(config_name)` initialises all extensions (`SQLAlchemy`, `Migrate`, `CORS`, `JWTManager`, `Marshmallow`) and registers blueprints. The `config_name` argument maps to `config/config.py::config_by_name`.

### Blueprints

| Blueprint | Prefix | Module |
|-----------|--------|--------|
| `main_bp` | `/` | `app/routes/main.py` — health check and index |
| `auth_bp` | `/api/auth` | `app/routes/auth.py` — login, register, `/me` |
| `users_bp` | `/api/users` | `app/routes/users.py` — user CRUD and roles |
| `tickets_bp` | `/api/tickets` | `app/routes/tickets.py` — ticket CRUD, comments, catalogs, dashboard |

### Models (`app/models/soporteplus_models.py`)

All SQLAlchemy models map to an existing remote database schema with Spanish-named columns and tables (PascalCase). The main entities are `Usuario`, `Tiquet`, `Comentarios`, `Documento`, `LogTransaccional`, and several catalog tables (`CatTiquet`, `EstadoTiquet`, `CatalogoCriticidad`, `Ubicaciones`, `Rol`, `Permiso`).

**Password hashing**: `Usuario` uses Werkzeug's `generate_password_hash`/`check_password_hash`. The legacy database stored passwords as SHA-256 hashes, so existing users may not authenticate if the hash method doesn't match.

### Role System

Roles are stored in the `Rol` table. `Usuario.is_admin` returns `True` when `ID_Rol == 1`.

| `ID_Rol` | Role |
|----------|------|
| 1 | Administrador |
| 2 | Técnico |
| 3 | Usuario (regular) |

Access rules: Admins and Técnicos (roles 1 & 2) see all tickets. Usuarios (role 3) only see tickets assigned to them or created by them.

### Key Implementation Quirk — `Tel_ext` as Creator ID

`Tiquet.Tel_ext` (nominally a phone extension field) is repurposed to store the `ID_usuario` of the ticket creator as a string. This is used to filter tickets for role-3 users even when the ticket is reassigned to a technician. When creating or querying tickets, `Tel_ext == str(user_id)` identifies the creator.

### Marshmallow Schemas

All Marshmallow schemas are defined inline within their respective route modules — there is no separate `schemas/` directory. `TiquetSchema` uses a `@pre_load` hook to convert date input from `dd-mm-yyyy` string (`fecha_apertura_input`) to a Python `date` object before validation.

### Validation

Input validation is handled by Marshmallow. Errors return HTTP 400 with an `errors` key. Global HTTP error handlers are registered in `app/utils/error_handlers.py` via `register_error_handlers(app)`.

### JWT Authentication

JWT tokens are generated by `Usuario.get_tokens()`, which returns both `access_token` (1 hour) and `refresh_token` (30 days). All API endpoints except `POST /api/auth/login` and `POST /api/auth/register` require a `Authorization: Bearer <token>` header.

### `app/services/`

This directory exists but is currently empty. Business logic is placed directly in the route handlers for now.
